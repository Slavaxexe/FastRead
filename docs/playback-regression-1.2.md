# Восстановление после регрессии APK 1.1

Проверка пользователем показала: после установки 1.1 пропусков стало значительно больше, в том числе на 250 WPM, где предыдущая версия работала нормально. Это подтверждённая пользователем регрессия сборки. Относить её к пределу A2 оснований нет. Предыдущие тесты JSDOM проверяли программные индексы и расписание, но не физический показ на BOOX.

В APK 1.2 / versionCode 3 отменён весь набор изменений пути показа, сделанный в 1.1:

- Удалены вызовы requestAnimationFrame из проигрывателя. Восстановлен setTimeout на полную выдержку каждого токена.
- Восстановлено присваивание textContent для трёх частей слова и подсказки. Переиспользование текстовых узлов и подавление повторных изменений классов отменены.
- Восстановлены периодические обновления окружающего интерфейса с прежним интервалом 750 мс. Заморозка счётчиков во время чтения отменена.

Эти изменения отменены вместе: данных для выбора одного из них как точной причины пока нет. Из 1.1 сохранены программный журнал, защита от устаревшего таймера/повторного play, отдельное сохранение позиции и устранение повторных операций на паузе. Токенизатор, настройки, библиотека, CSS и управление физическим режимом экрана при восстановлении не менялись. SDK для EPD и новый нативный рендер не добавлялись.

Восстановление проверяется программными тестами: полный порядок 71 токена инструкции при 250 WPM и 240 мс на токен без умных пауз; отсутствие зависимости от requestAnimationFrame даже при наличии этого API; задержка таймера без догоняния; смена скорости; отмена старого таймера; пауза/перемотка/перевод; восстановленный способ изменения DOM и обновления счётчиков. Такие проверки не подтверждают физическую видимость слов. Возвращение прежнего поведения на BOOX требует проверки APK 1.2 на устройстве.

Исторический отчёт `playback-audit-2026-10-24.md` помечен как отозванный в части оптимизаций 1.1.
